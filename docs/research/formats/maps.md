# Map files: world BSP and entities

- Game version / build: Steam build `1509967` (`Rage64.exe` 1.0.35.4669), with all DLC.
- Files examined: the 31 `.proc` files in `base/gameresources.resources`, and the `.entities`
  files of dusty8, wasteland1 and wasteland2, read in memory. No entity data was copied.
- Tools used: Python scripts built on [tools/resources.py](../../../tools/resources.py), and
  OpenRAGE's engine experiment (a stripped RBDOOM-3-BFG), which loads RAGE maps natively from these
  files.
- Confidence: **verified** for the `.proc` layout and the entity file syntax (both parsed in full
  and loaded in the engine); **inferred** for what `spawnOrientation` rows and the `!` marker mean;
  **unknown** for the other map files listed at the end.
- Date: 2026-11-01

## What we know

A map such as `maps/game/tracks/dusty8` is spread over several archive entries:

| File | Contents |
| --- | --- |
| `maps/game/<…>/<map>/_combo/<map>.proc` | The world BSP: areas and the tree that finds them |
| `maps/game/<…>/<map>/_combo/_area<N>.bmodel` | The geometry of area N (see [bmodel.md](bmodel.md)) |
| `maps/game/<…>/<map>/_combo/megamodel_*.bmodel`, `sky.bmodel` | Movers and other dynamic pieces, and the sky |
| `maps/game/<…>/<map>/_combo/<map>_occlusion.bmodel` | Probably occlusion geometry; a different structure |
| `maps/game/<…>/<map>/_combo/world.bcm`, `<map>/*.bcm` | Collision models (not studied yet) |
| `maps/game/<…>/<map>.entities` | The map's entities |

### `.proc`: the world BSP

A text file that starts `mapProcFile005 /* generated by buildCompositeBSPFromWorld */` and holds
only two of Doom 3's `.proc` sections, in the same syntax:

```
interAreaPortals { /* numAreas = */ 316 /* numInterAreaPortals = */ 0
}
nodes { /* numNodes = */ 315
/* node 0 */ ( 1 0 0 -620 ) 1 174
...
/* node 314 */ ( 0 1 0 39493 ) -315 -316
}
```

- Each node is a split plane (a, b, c, d) and two children. A positive child is another node; a
  negative child c is area −1 − c. In dusty8 every plane is axis-aligned.
- **No map has any portals**: all 31 `.proc` files have zero. Areas only divide space, from 104 in
  `bash_tv_entrance` to 1,764 in `wasteland1`; they don't decide visibility the way Doom 3's
  portals do.
- There are no inline models. Each area's geometry is its own `_area<N>.bmodel`, and every area
  number has one (316 for dusty8's 316 areas).

### `.entities`: the map's entities

id Tech 5's entity format, a text file:

```
Version 3
entity {
	layers {
		"layer/race/dusty8/dusty8_forward"
	}
	entityDef player_start_2 {
		inherit = "player/start";
		class = "idPlayerStart";
		expandInheritance = false;
		edit = {
			spawnPosition = {
				x = 959.8499755859;
				y = -5566.3715820313;
				z = -1028;
			}
			spawnOrientation = {
				mat = {
					mat[0] = { x = 0.6171839237; y = -0.7487040162; z = -0.2419219762; }
					...
				}
			}
		}
	}
}
```

- Each `entity` holds an optional `layers` list (the gameplay layers it belongs to; 175 of
  dusty8's 420 entities have one) and one `entityDef <name>` block.
- An `entityDef` has `inherit` (the declaration it builds on), `class` (the game class) and an
  `edit` block of settings. Values are numbers, quoted strings or nested blocks.
- Keys can carry a quoted type first, such as `"float" gravity = 1066.0;`.
- Some blocks are written `key = ! { … }`; the `!` probably marks a block that replaces the
  inherited one rather than merging with it (guess).
- Vector components that are zero are left out, so a missing `z` means 0.
- `spawnOrientation.mat` is a rotation matrix; its first row is the entity's forward direction
  (inferred: the player starts face along the race track's starting grid in dusty8).

Entity counts: dusty8 420, wasteland1 4,698, wasteland2 2,040. The most common classes in dusty8 are
`idEntityImposter` (93), `idAISplinePath` (49), `idDynamicEntity` (40), `idStaticEntity` (37) and
`idSound` (37). Player starts (`idPlayerStart`): dusty8 1, wasteland1 53, wasteland2 20.

### Coordinates

RAGE maps are larger than Doom 3 allows. Doom 3 limits coordinates to ±131,072 units; the largest
coordinates in RAGE's map geometry are 196,816 (wasteland2) and 152,232 (wasteland1). Every other
map in the base game's archive stays within ±80,000.

### Other map files

Each map also has `<map>.ambient`, `<map>.sbsp`, `<map>.script` and `<map>.bfoliage`, a
`globalshadows2.bin`, map-local material declarations (such as `mega.decl`) and a
`generated/buildgame/game/<…>/<map>.mapresources` list. None has been studied yet.

- The other map files above.
